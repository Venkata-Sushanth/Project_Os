# Phase 1 scope and delivery
Phase 1 implements the frontend foundation only. Navigation, mobile drawer, profile/organization menus and page finder are shell interactions. Page finder filters destinations, not project records. Preview organization choices demonstrate route context only, not membership, tenancy or authorization.

## Design
Light neutral canvas, restrained forest-green accent, compact system typography, consistent 10–12px panels, Lucide icons, visible keyboard focus and native modal dialogs. Desktop sidebar transitions to modal navigation at 900px; cards stack at 680px. No external image/font dependency. The overview illustration is explicitly a design concept, not task data.

## Preserved and updated
All Phase 0 documents are preserved except roadmap alignment to the user's latest fixed phases. The latest Phase 1 instructions supersede older statements assigning an interactive mock prototype to Phase 1; that work belongs to Phase 2. Predictive intelligence and the assistant remain reserved for Phases 7 and 8.

## Boundaries
No API, database, Prisma schema/migration, real authentication, policy evaluation, simulation calculation, approval execution, persistent audit or AI integration. Phase 1 requires no secrets or backend connection.

## Verification status
Source prepared through GitHub tools. Cloud build is configured to run lint, strict TypeScript and Next.js build. Results must be recorded from actual deployment checks; configuration alone is not a passing check. Browser responsiveness, keyboard and console verification remain pending until a running preview is inspected. No local dependency installation, build, test or development server is authorized.
